# 开发

Rust 原生引擎，Ratatui + rat-widget 单页表格。`catalog.json` 保存所有项目的名称、用途与操作，是功能清单的唯一来源。中英文名称分别显示；无中文名称的应用使用原名。

界面先显示，最多四路后台检测。执行全部时跨分类最多六路处理本地设置，安装最多六路，安装器互斥由 winget 管理。先处理本地设置与传递优化，再处理安装；输入法清理依赖微信输入法，桌面文件和开始菜单在安装后复查。单项失败保留可重试状态，不阻断无关项目；重试清除本轮检测缓存，重新读取网络恢复后的安装清单。

首次正常模式先执行所有可执行的本地设置，包括 UTF-8、开始菜单、服务和需要重新登录的 Shell 设置，然后统一准备安全模式或普通重启。安全模式执行受保护设置，也允许执行注册表、服务、BCD 等本地操作；不使用计划任务服务，混合项目中的任务留到正常模式核验。AppX、winget、DISM 和依赖桌面服务的操作在正常模式执行。安全模式退出前统一安排返回正常模式；返回后安装软件并清理输入法、桌面文件。一般只需安全模式往返的两次重启；安装器明确返回重启要求或本地操作失败后重试仍可能需要额外重启，不能将实际未生效状态标记完成。

界面采用 Catppuccin Latte / Mocha，通过 Windows 注册表通知实时跟随系统应用主题，仅收到变化时读取主题并重绘；经典控制台边缘同时更新。保留终端标题栏，内部不重复标题。表格滚动条和选择交互使用 rat-widget；滚轮、点击与拖动只选择，不执行。列表使用固定顺序：安全设置、本地设置、安装；不随检测、失败、重试或完成状态排序，也不自动移动选中行。检测队列显示待检测，只有真正开始读取状态的项目显示检测中；执行队列显示等待执行。滚动条滑块用空格背景填满，避免终端字体的字形行距造成断条。结果在顶部，底部显示选中项的用途和状态说明。重启快捷键为 R。

状态与日志位于 ProgramData，用户托盘展开助手位于 LocalAppData，检测临时文件位于 TEMP。手动启动不自动重启；仅自动续跑入口显示倒计时。右键菜单支持 Windows 10 / 11 样式切换，其余项目单向执行。

保留 Windows Time（`W32Time`）及 `Time Synchronization` 下的校时任务。执行“时间同步自动启动”时设为自动启动、移除服务触发器并立即运行，保留现有 NTP 配置；用户仍可在服务管理中修改。按 [Microsoft 方法一](https://learn.microsoft.com/en-us/troubleshoot/windows-client/active-directory/w32time-not-start-on-workgroup) 避免工作组默认触发器干扰自启。只读检测不修改配置，必须确认 SCM、注册表启动类型均为自动、触发器已移除且服务实际运行，才显示已设置。重启后核验使用 EXE 的 `--check`；系统拒绝读取的项目保留“读取受限”，不能按旧结果推断已完成。

跨设备接续在 CBS 清单中注册为桌面 Shell 的登录扩展：`CrossDeviceResumeHost` 使用接续 EXE，`CrossDeviceResumeService` 通过 `ShellHost.exe` 承载，并非 SCM 服务。通过当前用户的 `DisableCrossDeviceResume` 策略关闭，保留共享桌面宿主和 CBS 包。`%UserSid%` 在操作展开时替换为当前用户 SID。禁止对接续 EXE 添加拒绝执行权限；旧版本留下的 Everyone / ExecuteFile 拒绝项在执行此项时清除，其他权限保留。[策略说明](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-connectivity#disablecrossdeviceresume)。

## 构建与验证

开发机需要 Rust stable、Visual Studio C++ Build Tools（VCTools，含推荐的 Windows SDK）：

```text
python tools/build.py build --release --locked
python tools/build.py clippy --locked --all-targets -- -D warnings
python tools/build.py test --locked
python tools/measure_ui.py target/release/zero_security_windows.exe
python tools/check_console.py target/release/zero_security_windows.exe
```

Release 仅设置 `strip = true` 和 `lto = "thin"`，其余 profile 参数默认。MSVC 静态 CRT 用于单 EXE 分发。构建产物、调试记录和临时文件不提交，EXE 只上传 Release。不创建 CI。

本地自动化测试使用隔离数据和只读检测；`measure_ui.py` 通过隐藏 ConPTY 测量首屏、方向键和退出。在已优化目标机的登录用户会话测试实际 EXE：检测中执行全部、鼠标选择与滚轮、窗口缩放、单项执行、右键菜单双向切换、普通重启续跑及倒计时取消。单项执行通过临时改变文件显示设置验证，随后回到优化状态。新装系统的首次全量安装、卸载和 Defender 安全模式流程仍需独立验收。

0.7.3 实机验收：普通重启后 149 项已完成，2 项不参与操作，没有可执行项、失败项或遗留重启计划。隐藏 ConPTY 首屏约 42–180 ms，方向键约 19–39 ms；这些数字包含测试终端传输，不包含终端宿主窗口创建或 UAC 提权耗时。

语言栏的注册表 `ShowStatus=3` 与 TSF API 的 `TF_SFT_HIDDEN=8` 是不同编码，读写分别处理。AppX 清单跳过安装目录已不存在的孤立注册；卸载成功但文件仍待移除时显示重启生效。保留存储使用 DISM 英文输出，状态读取不区分大小写。已有重启计划再次执行时更新续跑 EXE，避免继续运行旧版本。

0.7.4 本机验证：ChatGPT 与 UniGetUI 使用本地 AppX / 卸载注册识别，不依赖 Store 源查询；当前状态已完成时清除旧错误。计划任务已禁用或已移除时不重复写入，写入返回错误但实际已禁用时按实际结果判定。临时 SYSTEM 任务验证禁用、重复禁用与移除后的检测，任务没有执行过。位置服务保持禁用，单项执行清除位置页面的隐藏策略，其余页面设置保留。本机两条失败记录已消除，续跑 EXE 已更新；未重启。失败提示与日志路径在同一段显示，按窗口宽度自然折行。

保留“应用请求位置时通知”开关，不隐藏位置设置。不管理应用启动项。浅色、深色布局、滚动条选择、检测中导航与窗口缩放已验证。隐藏 ConPTY 首屏约 52–67 ms，方向键约 1–2 ms。测试终端清除开发工具注入的 `NO_COLOR`，避免配色验证失真。

经典控制台隐藏系统滚动条后仍预留 17 像素，Ratatui 的字符网格无法覆盖。0.7.6 使用标准 OSC 4 将默认背景调色板同步为界面背景，退出时恢复，不更改终端配置；表头使用普通背景，底色仅表示选中行。验证时同时检查隐藏经典控制台的实际背景调色板和窗口尺寸，不能仅验证 ConPTY 字符网格。

远程诊断程序通过标准输入传输到目标机的 TEMP，不假设用户目录。系统参数和登录桌面检查在已登录用户的交互会话运行；服务会话的鼠标、键盘状态不能代表用户会话，枚举到零个窗口也不能用于判定没有弹窗。隐藏 Python 测试使用 `pythonw.exe` 和一次性交互任务。等待诊断 EXE 使用进程句柄，避免 `Start-Process -Wait` 等待它派生的后台进程。临时任务与程序在检查后清除。

## 0.8.1 输入法误报修正

`EnumEnabledLayoutOrTip` 只列出登记的输入配置，不能覆盖当前会话单独加载的键盘。实机出现 TSF 仅微信输入法，而 `GetKeyboardLayoutList` 同时包含中文 `08040804` 和美式 `04090409`，所以仅检查 TSF 会误报已设置。

完成状态同时核验 TSF 配置和当前会话加载布局；保留微信所需的中文基础布局，其余语言布局必须移除。清理先替换登记配置，再通过 `UnloadKeyboardLayout` 卸载会话残留；卸载失败保留失败状态，不标记完成。见 [当前布局枚举](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getkeyboardlayoutlist) 和 [卸载接口](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-unloadkeyboardlayout)。

回归测试覆盖“TSF 仅微信，但会话仍有美式键盘”的状态判断。另有默认忽略的本机测试：临时加载美式键盘，核验项目可设置，调用 Engine 的实际执行路径，再核验已设置且没有美式布局。仅在用户明确要求本机输入法清理时执行：

```text

```

## 0.8.2 检测状态说明

检测结果区分环境与读取问题：Defender 停止时，篡改防护显示“未运行”；没有处理对象显示“无需处理”；安全模式不具备所需服务的项目显示“返回正常模式执行”，不调用相关检测接口。以上状态自动跳过，并在底部解释原因。

Windows 返回访问拒绝或权限不足时显示“读取受限 · 可重查”，其他读取错误显示“状态待确认 · 可重查”。通过 IO / HRESULT 错误码区分权限问题，不解析本地化错误文案；见 [Windows 注册表访问权限](https://learn.microsoft.com/en-us/windows/win32/sysinfo/registry-key-security-and-access-rights)。原始错误按项目记录到 `checks.jsonl`，不将读取问题计为执行失败或完成，也不自动写入未确认的项目。Space 在这些行只发起重新检测，清除本轮检测缓存，保持选中行和列表顺序；实际执行失败继续保留红色可重试状态。

本机只读验收：篡改防护为未运行，增强钓鱼防护与系统保留存储为读取受限，没有泛化为无法检测，也未误标完成。检测逻辑与界面相关的 11 项测试通过，Clippy 无警告；隐藏 ConPTY 首屏 28.46 ms，方向键 0.60–0.77 ms，正常退出。未执行全量优化或重启。

## 0.8.3 位置开关保留用户控制

旧版本使用 `DisableLocation=1` 和禁用 `lfsvc`，会锁住 Windows 的位置开关。位置项目改为先关闭设备和当前用户的位置访问，再删除旧版 `DisableLocation` 策略，将 `lfsvc` 恢复为手动启动，保留原有触发器、设置页面和每个应用的独立选择。Windows 的位置设置由用户手动控制，见 [Microsoft 位置隐私说明](https://support.microsoft.com/en-us/windows/privacy/windows-location-service-and-privacy)。

`ServiceStart` 通过 `ChangeServiceConfigW` 修改 SCM 配置，使用 `QueryServiceConfigW` 读取实际启动类型，不能只改注册表 `Start` 后就判定服务已经恢复。此操作不停止或启动服务。位置项显示“已关闭 / 可关闭”；用户手动开启后，重新检测为可关闭，只有再次主动执行该项或执行全部才关闭。

本机已通过 Engine 的实际执行路径清理旧策略并恢复服务，普通位置访问保持关闭；重复执行不产生修改，也不要求重启。隔离注册表测试核验普通允许访问会变为可关闭、旧强制策略残留不能标为完成。本机修复测试默认忽略，仅在用户明确要求修复位置设置时执行：

```text
python tools/build.py test --locked repair_location_controls_on_this_machine -- --ignored --test-threads=1
```

验证没有打开前台窗口；设置应用已打开时，由用户返回上一页再进入位置页刷新。

两项位置相关测试与 Clippy 通过，Release EXE 的本机检测为已关闭；SCM 查询确认服务为手动启动，原有触发器完整保留。未执行全量优化或重启。

## 0.8.5 普通设置保留 GUI 恢复能力

## 0.8.6 任务栏固定项检测与说明

任务栏项目检测 Windows 保存的固定项，不代表当前可见的窗口按钮。旧版 `TaskbarNoPinnedList` 只隐藏固定项并阻止再次固定，原记录仍会保留；解除后正在运行的资源管理器可能还未刷新。见 [Microsoft 任务栏策略说明](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-taskbar#taskbarnopinnedlist)。本机只读枚举返回文件资源管理器、Microsoft Edge、Microsoft Store 共 3 项，资源管理器启动早于旧策略解除，隐藏状态尚未刷新是当前图标不可见的可能原因。

通过 Shell `IPinnedList3.EnumObjects` 枚举实际固定记录，停止将任意缓存值或残留 `.lnk` 判为固定项。接口身份与方法顺序见 [Chromium 实现](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/installer/util/taskbar_util.cc)，枚举签名见 [AppSwitcherBar 实现](https://github.com/adamecr/AppSwitcherBar/blob/master/net.adamec.ui.AppSwitcherBar/Win32/NativeInterfaces/IPinnedList3.cs)。该对象仅支持 STA；现有检测线程使用 MTA，直接创建会返回 `E_NOINTERFACE`，因此每次在短生命周期的 STA 线程中读取，不提供第二套检测路线。

TUI 显示“可清理”或“无固定项”，底部显示数量、名称及隐藏设置的刷新说明；等待重新登录时保留检测详情。后台修复旧锁定时仍保留用户固定项，同时记录 Shell 刷新要求。

## 0.8.10 关闭驱动自动更新、系统还原与休眠能力

按用户要求，自动驱动更新同时设置 `ExcludeWUDriversInQualityUpdate=1` 与 `SearchOrderConfig=0`，排除质量更新中的驱动并关闭设备安装时在线搜索，仍可手动安装。更新驱动排除通过本地组策略恢复，见 [Microsoft 驱动更新说明](https://learn.microsoft.com/en-us/windows/deployment/update/waas-wu-settings#do-not-include-drivers-with-windows-updates)。

系统还原用 [SystemRestore.Disable](https://learn.microsoft.com/en-us/windows/win32/sr/disable-systemrestore) 关闭系统盘保护，该调用同时关闭所有卷。清理旧 `DisableSR` / `DisableConfig` 锁定，保留系统保护的 GUI 开关，不禁用共享的 VSS / swprv 服务。检测读取 SPP 的 System Restore 客户端受保护卷列表，用户重新启用任意卷后即可显示待执行；不再根据缺失策略或没有还原点判断关闭。

新增独立“系统休眠”项，使用 [powercfg /hibernate off](https://learn.microsoft.com/en-us/troubleshoot/windows-client/setup-upgrade-and-drivers/disable-and-re-enable-hibernation) 关闭能力并移除 `hiberfil.sys`。检测同时验证 `HibernateEnabled=0` 和文件不存在；移除旧界面修复项中的开启休眠操作，避免全量并行执行互相覆盖。虚拟内存保留。

WMI crate 的方法输入使用具名 Serialize 结构体，不能传 HashMap。本机发现空 Drive 字符串写入方法参数返回 `0x80041006`；统一传非空系统盘路径，符合文档语义并通过实际调用，不引入第二套执行路线。本机应用测试独立默认忽略，旧普通界面修复测试不再包含这两项新禁用行为。

43 项常规测试及 Clippy 通过；本机三项应用、实际 WMI 调用及重复执行验证通过，无重启要求。休眠文件原大小 13,501,198,336 字节（约 12.6 GiB），现已移除；应用前后 pagefile.sys 大小一致，VSS / swprv 启动配置保留。发布 EXE 三项检测均已完成，powercfg 确认休眠及快速启动不可用。虚拟内存由 Windows 管理，验证保留状态，不将其他会话的历史文件大小作为固定期望。
