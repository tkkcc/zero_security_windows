# 开发文档

## 文档分工

README 只保留产品介绍、能力概览和下载入口。[使用指南](使用.md)说明操作、状态和设置范围；本文说明实现、界面规范、验证和发布。英文使用指南与中文保持一致。

文档维护当前行为。版本变更由 Git 历史记录；临时诊断脚本、设备恢复过程和验证输出放在忽略的 `artifacts/`，不进入产品清单或公开使用说明。

## 架构与执行

Rust 原生引擎，Ratatui + rat-widget 单页表格。`catalog.json` 是功能定义的唯一来源，保存中英文名称、功能、影响、操作与检测方式。

| 文件 | 职责 |
| --- | --- |
| catalog.json、src/model.rs | 项目定义、状态及详情表达 |
| src/controller.rs | 检测、执行队列与依赖调度 |
| src/engine.rs、src/checks.rs | 操作执行与结果核验 |
| src/workflow.rs、src/store.rs | 重启续跑、状态持久化与日志 |
| src/tui.rs | 表格、主题、选择与详情排版 |
| src/native.rs、src/registry.rs、src/preferences.rs | Windows 接口、注册表与普通首选项 |
| src/apps.rs、src/mitigation.rs、src/tray.rs | 软件管理、防护配置与托盘展开助手 |

界面先显示，后台最多四路检测。本地操作和安装阶段各最多六路并行，跨分类调度，安装器互斥由 winget 管理。先执行本地设置与传递优化，再处理重启边界和软件安装；输入法依赖微信输入法，桌面清理与开始菜单在安装后复查。失败只阻断依赖它的项目，重试清除相关检测缓存。

正常模式先合并可执行的本地设置，再进入安全模式处理受保护项。安全模式也支持注册表、服务和 BCD 操作；计划任务留到正常模式核验，AppX、winget、DISM 和依赖桌面服务的操作在正常模式执行。返回正常模式后继续安装和清理。重启依据实际生效条件安排，不承诺固定次数。

状态和执行日志保存于 `%ProgramData%\ZeroSecurityWindows`，用户助手位于 `%LocalAppData%\ZeroSecurityWindows`，临时文件位于 `%TEMP%`。状态记录启动与登录会话，续跑计划保存执行阶段和剩余项目；再次执行时更新续跑 EXE。手动启动不自动重启，自动续跑入口的倒计时可取消。

## 检测与完成判定

状态标签及用户操作统一见[使用指南](使用.md#状态与详情)。检测只读取设置，执行后核验实际结果。

- 完成以项目可配置目标为准；运行时强制或程序自行启用的防护在详情中说明，不形成重复待办。尚未生效的更改保留重启或重新登录状态。
- 系统访问限制、临时读取问题和执行失败分别处理。权限问题依据 IO / HRESULT 错误码识别，不解析本地化错误文案，也不伪装成完成。
- 当前检测结果决定摘要与续跑结束。完成或无需处理时清除旧执行错误；历史失败记录不能覆盖当前完成或跳过状态。
- 所需防护后台已禁用且停止时，依赖它的提醒无需另行处理；后台不存在时按无处理对象判断。

## Windows 接口约束

- **普通设置**：使用首选项或原生接口，保留手动控制及依赖服务。清理策略只删除相关值；任务恢复只依据本工具成功修改的操作记录。开始固定列表使用 `applyOnce=true`，保留后续手动固定能力。独立迁移项和通用通知控制不进入功能清单。
- **服务**：启动类型通过 SCM 修改并同时核验 SCM 与注册表。诊断等后台服务仅关闭后续启动，不停止当前服务。每用户服务按模板配置；实例需要新登录会话时保留生效标记，重启资源管理器不能提前清除。
- **位置与下载**：位置关闭访问及请求通知，保留 lfsvc 的手动触发启动；传递优化通过 `MSFT_DeliveryOptimizationConfig.SetDownloadMode` 写入普通选择，移除强制下载模式策略，保留正常下载。Edge 后台设置使用可覆盖的 Recommended 默认值。
- **系统还原与休眠**：通过 `SystemRestore.Disable` 关闭各卷保护，传入非空系统盘路径，保留 VSS / swprv 和系统保护开关；休眠由 powercfg 关闭，同时核验配置与 hiberfil.sys，不修改虚拟内存。
- **SysMain 与时间同步**：应用预读关闭预读配置与 ApplicationPreLaunch，保留 SysMain 自动启动、内存压缩和内存页合并；不调用不受支持的 MMAgent 方法。时间同步核验自动启动、触发器移除及实际运行，保留 NTP 配置和校时任务。
- **输入法**：完成判定同时检查 TSF 登记配置和 `GetKeyboardLayoutList` 的会话布局；保留微信所需中文基础布局，替换输入列表并卸载额外布局。语言栏注册表 ShowStatus 与 TSF 标志使用不同编码。
- **任务栏与应用**：固定项通过 `IPinnedList3.EnumObjects` 在 STA 线程枚举，不根据缓存或残留快捷方式推断。AppX 跳过安装目录缺失的孤立注册；卸载后文件尚待移除时保留重启状态。
- **桌面宿主**：跨设备接续使用专门策略；保留共享 CBS 包与 ShellHost，不通过拒绝执行权限禁用宿主。
- **安全状态**：LSA 查询 `ProcessProtectionInformation`，仅判断 PS_PROTECTION 的低三位 Type，审计位不代表保护。DEP 区分启动配置、`GetSystemDEPPolicy` 与当前进程状态。程序防护和驱动签名分别报告配置目标与运行时保护；不修改运行中进程的保护等级。钓鱼防护只使用公开的 ServiceEnabled 策略，不访问受保护内部键。

相关接口：[每用户服务](https://learn.microsoft.com/en-us/windows/application-management/per-user-services-in-windows)、[输入法布局](https://learn.microsoft.com/en-us/windows/win32/tsf/installlayoutortip)、[DEP 限制](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/determine-hardware-dep-available)、[进程防护策略](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ne-winnt-process_mitigation_policy)。

## 界面与文案

文案面向公开发行的中英文产品，描述当前功能和影响，不出现特定设备、调试经过或恢复专项。

| 位置 | 内容 |
| --- | --- |
| 右侧状态 | 简短结果，不混入重试提示、日期、计数或错误 |
| 底部功能 | 执行目标 |
| 底部影响 | 必要的范围、后果与平台限制 |
| 底部状态 | 检测结果、日期、数量、具体对象及运行状态 |
| 底部操作 | 当前可用的下一步；执行中不提示不可用操作 |
| 底部错误、日志 | 失败原因与完整日志位置；访问限制原始信息归入检测日志 |

列表顺序固定为安全设置、本地设置、安装，不随状态排序；重试保持选中行。鼠标只选择。详情换行与正文对齐，按内容调整高度，保持选中项可见；长错误保留操作和日志入口。防护计数说明所统计的进程，不把有重叠的计数相加。

采用 Catppuccin Latte / Mocha，通过注册表通知跟随 Windows 应用主题。滚动条滑块用空格背景填满；经典控制台每次实际重绘后隐藏系统滚动条，用 OSC 4 同步边缘背景，退出时恢复，不改终端配置。

## 构建与验证

需要 Rust stable、Visual Studio C++ Build Tools 的 VCTools 与 Windows SDK。`tools/build.py` 自动导入 MSVC / SDK 环境，隐藏运行 Cargo。

```text
python tools/build.py test --locked -- --test-threads=1
python tools/build.py clippy --locked --all-targets -- -D warnings
python tools/build.py build --release --locked
```

按修改范围运行必要检查；仅文档修改检查内容与链接即可。测试、Clippy 和构建顺序执行，避免争用 Cargo 构建锁。修改版本后先用 `python tools/build.py check --offline` 更新 Cargo.lock，再使用 `--locked`。

界面修改使用隐藏终端验证，覆盖中英文窄窗口、长详情、选中项可见性和退出恢复：

```text
python tools/measure_ui.py target/release/zero_security_windows.exe
python tools/check_console.py target/release/zero_security_windows.exe
```

前者测量首屏、导航与退出，后者检查经典控制台背景、滚动条和恢复。清除测试环境注入的 NO_COLOR；同时验证 ConPTY 与经典控制台，不用字符网格结果代替宿主状态。

自动化测试默认使用隔离数据或只读检测。修改设备的测试默认忽略，仅在明确授权相应操作时运行，并通过实际 Engine 路径初始化执行权限。首次安装、卸载和安全模式往返需在对应环境验收；配置读取不能代替桌面行为验证。键鼠和窗口状态在已登录用户会话检查，服务会话结果不能代表用户桌面。

只读报告可指定输出文件：

```text
target/release/zero_security_windows.exe --check artifacts/check.json
```

开发验证不弹出前台窗口，不自行重启设备。复杂临时脚本先保存为 Python 文件；等待子进程使用进程句柄，避免连同派生后台程序一起等待。

## 提交与发布

在 master 上提交并推送，不创建分支或 CI。保持实现简单，优先使用现有库能力；测试验证行为，避免文案关键词匹配或重复检查。

Release 使用 MSVC 静态 CRT，profile 仅设置 `strip = true` 和 `lto = "thin"`，分发单个 EXE。构建产物与临时记录不提交 Git。

创建 GitHub Release 时，`--target` 指向完整提交 SHA，附件使用 `target/release/zero_security_windows.exe`。下载命令退出后，再核验 latest 附件与本地文件的 SHA256；复制给测试者的文件使用同一份已核验附件。文档修改直接推送，不单独升级程序版本或重发 EXE。
